## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define and implement a versioned OKC extension for typed document relationships while preserving OKF v0.2 interoperability. Canonical Markdown links remain the portable graph; typed metadata enriches those links for OKC-aware consumers. Unknown relationship types and missing targets remain representable and diagnosable rather than making an otherwise valid OKF document unreadable.
<!-- SECTION:DESCRIPTION:END -->

<!-- AC:BEGIN -->

- [x] #2 Known relationship types have documented semantics while unknown types are preserved and returned without parse failure

- [x] #4 Typed edges are persisted through a migration that preserves all existing untyped links and supports idempotent rescan

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## OKC-00039.01 Implementation Plan — Portable Typed-Link Extension

Goal: a versioned, additive typed-relation layer for the document graph that preserves OKF v0.2 portability and never rejects documents (AC #1–#7).

### 1. Extension format (frontmatter, additive to OKF v0.2)

Anchored in OKF spec §4.1 Extensions (okf-spec.md:205-208: producers MAY add any keys, consumers SHOULD preserve unknown keys, MUST NOT reject unrecognized fields). One new versioned frontmatter block (`src/parser/yaml.rs` preserves all other unknown keys in `custom`):

```yaml
typed_links:
  version: 1
  links:
    - target: /data/metrics.md
      relation: depends-on
      anchor: optional-anchor   # optional
```

- `version` required int; current scheme = `1`. `version != 1` → preserved verbatim in `custom`, surfaced as a warning, never a parse failure.
- `links`: list of `{ target, relation, anchor? }`.
  - `target`: bundle-relative path (recommended `/...`) or absolute URL/external; resolved via the same resolver as canonical Markdown links.
  - `relation`: free-form string. Known vocabulary documented: `references` (default), `depends-on`, `imports`, `extends`, `implements`, `derived-from`, `supersedes`, `related-to`. Unknown values preserved and returned (AC #2), never rejected.
  - `anchor`: optional narrow.
- Malformed block shape (not a map / missing links / missing target) → preserved in `custom`, ParseStatus remains Ok/Partial with a warning (AC #2 tolerance).

### 2. Model
- `LinkInfo` (src/model/document/content.rs:127) gains `relation: Option<String>` (None = canonical/untyped); `resolve_links` leaves None → backward compatible.
- New `TypedLink { target, anchor: Option<String>, relation }` (new model type, e.g. `src/model/document/typed_link.rs`).
- `FrontMatter` (src/model/document/frontmatter.rs) gains `typed_links: Vec<TypedLink>` (default empty).

### 3. Parser
- `src/parser/yaml.rs`: parse `typed_links` block into `FrontMatter.typed_links` per §1 rules (version gate, malformed tolerance).

### 4. Migration & rescan (AC #4)
- `src/index/migrations.rs`: add schema version 3 —
  - `ALTER TABLE links ADD COLUMN relation TEXT` guarded by `pragma_table_info('links')` (robust for fresh + existing DBs; existing untyped rows keep `relation = NULL`, preserved).
  - `CREATE INDEX IF NOT EXISTS idx_links_relation ON links(relation)`.
- Mirror `relation TEXT` column in the parallel `links` DDL in `src/index/graph_store.rs:41-49` so both schema definitions agree (no behavior change; migrations run first at database.rs:75/:111).
- Idempotent rescan: write path already DELETE-then-INSERT per source doc (`src/index/document_store/links.rs insert_links/insert_links_tx`) — typed edges derive from the same parsed doc, so unchanged docs reproduce identical rows and changed docs are reprocessed. No duplicates.

### 5. Persistence & merge (AC #1, #6)
- Extend `document_store/links.rs` insert path to persist nullable `relation`.
- In `database.rs` store_parsed_document path, merge `FrontMatter.typed_links` with canonical `ParserResult` links:
  1. Resolve each typed target; check existence in bundle.
  2. Match: resolved target == a canonical Markdown link from same source → annotate that `LinkInfo.relation` (canonical edge enriched, not duplicated).
  3. Augment: no matching canonical link → append a new typed edge in the SAME `links` table (participates in get_links/get_backlinks/traverse; not a shadow graph).
  4. Broken target (AC #3): missing from bundle → warning (existing eprintln broken-link style + scan_errors if used), edge kept with `exists_in_repository=0`, document still indexed.
- Conflict → portability diagnostic + deterministic resolution (AC #6), documented:
  - P1 annotation-wins: typed relation over a canonical Markdown link target labels that edge; canonical link stays present/portable (relation is metadata only); diagnostic emitted once.
  - P2 typed-only: augment edges flagged as OKC-extension; diagnostic notes they are not portable to OKF-only consumers.
  - P3 duplicates: same source→target with different relations → last-declared wins (deterministic by declaration order); diagnostic emitted.

### 6. Graph reads / traversal (AC #5)
- `src/index/graph.rs`:
  - `get_links(path, relation_filter: Option<&str>)` → SELECT `relation`; filter `AND l.relation = ?` when Some; None = all edges incl. relations.
  - `get_backlinks(path, limit, relation_filter)` similarly.
  - `traverse_graph`: repair the existing no-op relations filter — when non-empty, `l.relation IN (...)` (NULL/untyped edges excluded under a specific filter; empty filter = all, unchanged default). Edge `GraphEdge.relation` = typed relation if present else existing `links_to`/`linked_from` default.
- `src/index/traits.rs GraphStore` + both impls updated for the new signatures.

### 7. Service & MCP (AC #5, backward compatible)
- `src/service/graph.rs`: wire optional relation filter through get_links/get_backlinks; traverse unchanged signature (already has `relations`).
- `src/transport/mcp/mod.rs`: get_links (:439) / get_backlinks (:467) accept optional `relation` input; `LinkInfoOutput` gains optional `relation` with `skip_serializing_if = "Option::is_none"` (legacy JSON byte-identical when absent). traverse (:493) routes `relations` into traverse_graph (fixes current no-op).
- `src/transport/mcp/types.rs:219`: `relations`/`relation` already exist — reuse.
- CLI traverse (main.rs/cli.rs) unchanged externally; prints typed relation.

### 8. Documentation
- New `docs/references/okc-typed-links.md`: versioned format, known vocabulary, resolution rules P1–P3, diagnostics, portability tie to OKF §4.1/§6.1.
- `docs/architecture.md`: typed-link extension + relation-aware graph.
- README.md graph section (lines 43, 63, 131): note typed-link support in `okc traverse`.

### 9. Tests (AC #7) — tests/integration_tests.rs + parser unit tests
1. Untyped bundle → get_links/get_backlinks/traverse identical to pre-extension (relation None, default labels).
2. Known relation persisted; traverse/`get_links` filter returns typed edges.
3. Unknown relation preserved, parse succeeds.
4. Broken typed target → warning + `exists_in_repository=0`, doc indexed.
5. Migration v2→v3 preserves untyped links; adds column; graph queries intact.
6. Rescan idempotent (twice = same edges; edited doc = exact rewrite).
7. Relation filtering on traverse (empty = all; specific = typed only).
8. Relation filter on get_links/get_backlinks; unfiltered default unchanged.
9. Backward-compatible MCP responses (relation omitted when None; default params unchanged).
